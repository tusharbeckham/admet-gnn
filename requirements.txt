# =============================================================
#  ADMETriage -- Python dependencies (TRAINING SIDE ONLY)
# =============================================================
#
#  This environment exists to produce one file: model.onnx.
#  It is never on the request path. Inference is Rust (see crates/).
#
#  Recommended installer is uv -- roughly 10x faster than pip and it
#  resolves the torch CPU index cleanly:
#      curl -LsSf https://astral.sh/uv/install.sh | sh
#      uv venv && source .venv/bin/activate
#      uv pip install -r requirements.txt
#
#  Install torch from the CPU index explicitly. The default PyPI wheel
#  drags in ~2.5 GB of CUDA libraries you will never use, because
#  training on datasets of 600-13,000 molecules is CPU work:
#      uv pip install torch --index-url https://download.pytorch.org/whl/cpu
#
# -------------------------------------------------------------
#  REMOVED FROM THE PREVIOUS VERSION -- read before re-adding
# -------------------------------------------------------------
#  torch-geometric
#  torch-scatter
#  torch-sparse
#
#  PyG aggregates neighbours with torch_scatter ops that have NO ONNX
#  equivalent, so a PyG model cannot be exported to a portable artefact
#  and therefore cannot be served from Rust. The whole architecture
#  depends on that export working. The model uses padded dense adjacency
#  and torch.bmm instead. Do not reintroduce these packages.
#  Refs: pyg-team/pytorch_geometric#8415, pytorch/pytorch#65138
#
#  fastapi / uvicorn / python-multipart / httpx
#
#  Serving is Axum in Rust. A second Python HTTP layer would duplicate
#  the API surface, split the test suite, and contradict the submitted
#  synopsis. If you need a throwaway debug endpoint during training,
#  install it ad hoc -- do not pin it here.
# =============================================================

# --- Core ML ---
torch>=2.5                    # install from the CPU index (see above)

# --- ONNX export + verification ---
onnx>=1.17
onnxruntime>=1.20             # used to verify the export in-process
onnxscript>=0.1.0             # required by torch.onnx.export(dynamo=True)

# --- Cheminformatics ---
rdkit>=2024.3.1

# --- Datasets: Therapeutics Data Commons ---
#  PyTDC is DELIBERATELY NOT INSTALLED HERE. See requirements-data.txt.
#
#  PyTDC 1.1.15 -- the latest release, and unchanged for well over a year
#  -- pins rdkit>=2023.9.5,<2024.3.1. Current rdkit is 2026.03.x.
#  Installing it here would drag this project's cheminformatics core back
#  two and a half years. It also pulls transformers, accelerate, datasets,
#  evaluate, huggingface-hub, cellxgene-census, tiledbsoma and gget --
#  none of which this project uses.
#  Ref: github.com/mims-harvard/TDC/issues/374
#
#  TDC is a build-time data acquisition tool, not a runtime dependency.
#  It is needed once per endpoint to fetch raw SMILES and labels, then
#  never again. So it lives in its own throwaway environment:
#      uv venv .venv-tdc --python 3.12
#      .venv-tdc\Scripts\Activate.ps1
#      uv pip install -r requirements-data.txt
#      python training/data/download.py
#
#  HARD RULE: download.py performs NO chemistry. It fetches and writes
#  raw CSV, nothing else. Every RDKit operation -- salt stripping,
#  canonicalisation, InChIKey, scaffold assignment, featurisation --
#  happens in THIS environment against the single pinned rdkit below.
#  Splitting chemistry across two rdkit versions is exactly how feature
#  skew (risk R3) gets in, and it is invisible until metrics disagree.

# --- Data handling ---
numpy>=1.26,<3
